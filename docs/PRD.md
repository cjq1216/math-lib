## 1. 项目背景与目标

### 1.1 背景
培训机构在数学教学实践中面临三大痛点：
1. **题库散落**：题目分散在 Word/PDF/老师个人电脑中，无法复用、检索困难
2. **组卷低效**：每次出试卷/作业需手动选题、编排，工作量大且难以保证难度均衡
3. **学情不可见**：学生对知识点的掌握情况依赖老师经验判断，缺少数据支撑，难以针对性辅导

### 1.2 目标
构建一套**面向培训机构数学教研**的智能化题库与学情分析系统：
- 集中管理 7-9 年级数学题目（结构化 + 标签化）
- 支持 Word/PDF 试卷批量入库
- 智能组卷（按难度、题型、知识点、预估时长）
- 班级与学生管理（教师代维护学生信息）
- 学情分析（薄弱知识点定位、针对性出题、试卷质量分析）

### 1.3 非目标（MVP 不做）
- ❌ 学生端 App / 小程序（学生不登录系统）
- ❌ 实时答题监考 / 防作弊
- ❌ 多学科（仅数学 MVP）
- ❌ SaaS 多租户计费
- ❌ 几何作图工具（占位，后续迭代）
- ❌ 主观题 AI 自动判分

## 3. 核心业务流程

### 3.1 题库建设流程
```
教师录入题目（手动 / Word导入 / PDF导入）
  → 系统调用 LLM 自动切题 + 打标 + 识别公式
  → 教师人工校对（界面：左侧原文，右侧结构化结果）
  → 入库（含题目 / 答案 / 解析 / 知识点 / 难度 / 题型）
```

### 3.2 组卷出题流程
```
教师创建试卷
  → 设置约束：总分 / 题型配比 / 难度分布 / 必含知识点 / 作答时间
  → 系统调用智能组卷算法（分层贪心 + 知识点约束校验）
  → 预览试卷（含历史卷相似度检测 / 卷内雷同检测）
  → 调整 / 重新生成
  → 关联班级 → 下发作业 / 导出 Word / PDF
```

### 3.3 学情分析流程
```
教师录入学生作答结果（单题对错 / 分数 / 用时）
  → 系统聚合计算：
      • 每生正确率（按知识点 / 题型 / 难度）
      • 薄弱知识点 Top N
      • 班级整体表现
  → 系统推荐针对性练习（基于薄弱知识点智能选题）
  → 教师可一键生成针对性作业
```

## 5. 详细功能说明（MVP 范围）

### M1. 用户与认证
- **登录**：用户名 + 密码（JWT）
- **角色**：机构管理员 / 教师
- **密码策略**：8 位以上、bcrypt 加密
- **会话**：JWT（access_token + refresh_token）

### M2. 题库管理
- **题目字段**：题号 / 题干（含 LaTeX 公式）/ 选项 / 答案 / 解析 / 题型 / 难度（1-5）/ 知识点（多选）/ 来源 / 标签
- **题型**：单选 / 多选 / 填空 / 判断 / 解答 / 证明
- **CRUD**：创建 / 列表（分页 + 过滤）/ 查看 / 编辑 / 删除（软删）/ 批量操作
- **富文本编辑器**：Tiptap + KaTeX（LaTeX 公式实时预览）
- **媒体资源**：图片 / 公式截图（解耦存储 + MD5 去重）
- **向量检索**：基于 sqlite-vec 的题目相似度检索（去重 + 相似题推荐）

### M3. 知识点管理
- **树形结构**：3 级（章 → 节 → 知识点）
- **范围**：7-9 年级数学（人教版 / 北师大版，可切换）
- **字段**：编号 / 名称 / 父节点 / 学段 / 难度 / 描述
- **操作**：增删改 / 拖拽排序 / 导入 / 导出（JSON）

### M4. 智能组卷
- **约束输入**：
  - 总分（必填）
  - 作答时长（默认 90 分钟）
  - 题型配比（如：选择 20 题、填空 10 题、解答 5 题）
  - 难度分布（如：易 30% / 中 50% / 难 20%）
  - 必含知识点（覆盖度保证）
  - 禁含知识点
- **算法**：分层贪心 + 知识点约束检查（生产首选）
- **校验**：
  - 必含知识点是否覆盖（缺则替换）
  - 卷内雷同检测（向量检索）
  - 与历史 3 次考试相似度检测
- **扩展**：AB 卷生成 / 预估时长计算
- **保存**：试卷可保存为模板复用

### M5. 多格式导出（MVP）
- **Markdown**：含 LaTeX 公式（在 Obsidian/VSCode/在线 Markdown 渲染）
- **Word (.docx)**：含公式（转 OMML 或图片）/ 答案页 / 解析页
- **PDF**：第二批（Typst 集成）

### M8. 学生与班级管理
- **学生信息**：姓名 / 学号 / 性别 / 年级 / 联系电话 / 备注
- **录入方式**：单条录入 / Excel 批量导入（.xlsx）
- **班级**：名称 / 年级 / 学期 / 关联学生 / 关联教师
- **数据隔离**：教师只能看到自己班级的学生（机构管理员看全部）

### M9. 作业/试卷下发
- **作业类型**：作业（不限时）/ 测验（限时）
- **创建流程**：选题 → 设置分值 → 关联班级 → 设置截止时间
- **状态**：草稿 / 已下发 / 已截止 / 已批改

### M10. 成绩录入与分析
- **录入方式**：
  - 单题录入（对/错 + 得分）
  - 整卷录入（总分 + 各题得分）
  - Excel 批量导入
- **自动统计**：
  - 每生各题得分
  - 班级整体平均分 / 最高分 / 最低分 / 标准差
  - 各题难度 / 区分度
  - 各知识点正确率

### M11. 学情分析
- **个人视图**（教师看学生）：
  - 知识点掌握雷达图
  - 历史成绩趋势
  - 薄弱知识点 Top 5（带题目举例）
- **班级视图**（教师看班级）：
  - 整体知识点掌握分布
  - 进步 / 退步学生
  - 班级排行（按平均分）
- **试卷视图**：
  - 难度分布（应然 vs 实然）
  - 区分度分析
  - 失分点分析

### M12. 针对性出题
- **输入**：学生 / 班级 + 目标题量 + 难度区间
- **算法**：
  - 从该生薄弱知识点 Top N 中选题
  - 排除最近已做过的题（去重）
  - 难度匹配
- **输出**：针对性练习卷（可一键加入作业/导出）

### M19. 备份与运维（MVP 基础）
- **数据库**：每日自动备份（SQLite 文件直接 cp）
- **媒体文件**：本地存储 + 定期打包备份
- **日志**：操作日志（用户 / 时间 / 操作 / 对象）
- **监控**：基础健康检查接口

## 8. 风险与约束

### 8.1 业务风险
| 风险 | 影响 | 应对 |
|---|---|---|
| 标签体系梳理拖延 | 整个项目卡住 | 第 1 周必须列 50 个核心知识点骨架；边做边补 |
| 公式识别率 < 90% | 校对工作量大 | 人工校对界面兜底；预留 20% 时间给校对 |
| 教师不录入学生作答数据 | 学情分析失效 | 设计"批量 Excel 导入"降低录入门槛 |
| 学生作答数据不真实 | 分析结果误导 | 录入界面清晰 + 教师 review |

### 8.2 技术风险
| 风险 | 影响 | 应对 |
|---|---|---|
| SQLite 单写者并发瓶颈 | 后期可能需要切换 | SQLModel + Alembic 设计就是为此；切换成本极低 |
| MiniMax API 限流 | 切题/打标卡住 | 本地 Ollama 兜底；批量异步处理 |
| 移动端体验差 | 教师/管理员不便 | Tailwind 响应式 + 后续 PWA 优化 |

### 8.3 外部依赖
- **MiniMax API**：主 LLM（用户已有 Key）
- **Ollama + Qwen2.5-14B**：本地兜底（完全离线可用）
- **LaTeX-OCR (pix2tex)**：公式识别（开源，本地）
- **PaddleOCR**：扫描 PDF 文字识别（开源，本地）

## 12. 结构化设计规格（v1.1 新增）

### 12.1 题目模型

**主表 `questions`**：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| stem | TEXT NOT NULL | 题干（LaTeX/Markdown）|
| stem_html | TEXT | 渲染后 HTML 缓存 |
| question_type | VARCHAR(20) | choice_single / choice_multi / fill / judge / solution / proof |
| difficulty | SMALLINT | 1-5 |
| total_score | FLOAT | 题目总分（默认 10）|
| default_score | FLOAT | 每空/每问分数（填空题用）|
| source_id | INTEGER FK | 来源文件 |
| source_page | INTEGER | 来源页码 |
| source_question_no | VARCHAR | 原题号 |
| checksum | VARCHAR(64) | 内容 hash |
| embedding | VECTOR(1024) | 向量 |
| created_at / updated_at | TIMESTAMP | 时间戳 |
| is_active | BOOLEAN | 软删 |

**子表 `sub_questions`**（复合题小问）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| question_id | INTEGER FK | 外键 → questions |
| label | VARCHAR | 小问标签："(1)" "(2)" |
| stem | TEXT | 小问题干 |
| score | FLOAT | 本小问分数 |
| display_order | INTEGER | 排序 |

**答案表 `question_answers`**（多空独立）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| question_id | INTEGER FK | 关联题目 |
| sub_question_id | INTEGER FK NULL | 关联到具体小问 |
| blank_index | INTEGER | 空号 1/2/3... |
| answer_text | TEXT NOT NULL | 答案文本 |
| is_primary | BOOLEAN | 是否首选答案 |
| match_rule | JSON | 等价规则（正则/多种写法）|

### 12.2 试卷模型（含快照）

**主表 `papers`**：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| title | VARCHAR | 试卷标题 |
| description | TEXT | 描述 |
| total_score | FLOAT | 总分 |
| duration_minutes | INTEGER | 时长 |
| status | VARCHAR | draft / published / archived |
| constraint_json | JSON | 组卷约束快照 |
| created_by | INTEGER FK | 创建者 |
| created_at / updated_at | TIMESTAMP | |

**关联表 `paper_questions`**（含快照）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| paper_id | INTEGER FK | 试卷 |
| question_id | INTEGER FK | 题目（保留关联但可读快照）|
| display_order | INTEGER | 题号 |
| section | VARCHAR | 大题号：I/II/III |
| score | FLOAT | 本卷中本题分数 |
| stem_snapshot | TEXT | 题干快照 |
| answer_snapshot | TEXT | 答案快照 |
| analysis_snapshot | TEXT | 解析快照 |

### 12.3 知识点体系（统一树形）

**表 `knowledge_points`**：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| code | VARCHAR | 编号（7-1-001 表示七上第一章第一节）|
| name | VARCHAR NOT NULL | 知识点名 |
| parent_id | INTEGER FK | 父节点，0 为根 |
| grade | SMALLINT | 学段 7/8/9 |

## 13. 图片与媒体资源策略（v1.1 新增）

### 13.1 存量策略（MVP 立即实施）
- 纯图片存储（PNG/JPG/SVG）
- MD5 去重（相同图只存一份）
- N:M 关联（一张图可用于多题）
- 三种 usage_type 全支持：`stem` / `option` / `analysis`

### 13.2 存储位置
- 本地文件系统：`E:\work\math-lib\data\images\`
- 目录分类：`question_images/` / `option_images/` / `analysis_images/` / `formula_images/`
- 文件命名：`{uuid}_{usage}_{关联ID}.{ext}`

### 13.3 MVP 必做功能
1. MD5 去重上传（自动检测已有图）
2. 多题复用（同一图关联多题）
3. 自动编号导出（"图1"、"图2"）
4. 同图检测（录入新题时向量检索相似图）

### 13.4 未来增量（L1 标注层）
- 在已有图上叠加标注（字母、辅助线、阴影）
- 表 `media_annotation`：存储 JSON 标注
- 简易编辑器：点几个字母、画几条线
- 工作量预估：半天到 1 天
- 优先级：MVP 后期

### 13.5 不做
- ❌ 内嵌几何画板（L3，2 周工作量）
- ❌ 自动检测几何对象（复杂，需求不强）

### 13.6 数据表

**`media_resource`（统一管理所有二进制素材）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |

| original_name | VARCHAR | 原始文件名 |
| storage_path | VARCHAR | 存储路径 |
| access_url | VARCHAR | 访问 URL |
| file_size | BIGINT | 文件大小 |
| mime_type | VARCHAR | MIME 类型 |
| md5_hash | VARCHAR(32) | MD5 去重 |
| width / height | INTEGER | 尺寸 |
| source | VARCHAR | 来源：upload / ocr / generated |
| created_at | TIMESTAMP | |

**`question_media`（题目-媒体关联，N:M）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 主键 |
| question_id | INTEGER FK CASCADE | 关联题目 |
| media_id | INTEGER FK CASCADE | 关联媒体 |
| usage_type | VARCHAR | stem / option / analysis / attachment |

| alt_text | VARCHAR | 替代文本 |
| UNIQUE | (question_id, media_id, usage_type) | 防重复 |
